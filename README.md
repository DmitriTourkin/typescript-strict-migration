# Типобезопасность на TypeScript: миграция JS-проекта в строгий режим — от any до размеченных объединений и проверки данных на границах приложения

> Изучить проектирование типов в TypeScript: размеченные объединения, обобщённые, утилитные и
> брендированные типы. Перевести JavaScript-проект с заранее внесёнными ошибками на TypeScript
> в строгом режиме без `any`, исправить найденные компилятором ошибки и добавить проверку ответов

> ошибках и видеоотчёт.

## О проекте

Учебный проект. Перед вами небольшое **веб-приложение интернет-магазина на JavaScript**: оно
загружает заказы с сервера, показывает их списком, считает выручку, фильтрует по статусу и
открывает чек заказа. В код заранее внесены ошибки, и часть из них видна, только если
понажимать на разные элементы интерфейса.

Ваша задача: **перевести приложение на TypeScript в строгом режиме** и с помощью компилятора
найти и исправить эти ошибки. Кроме того, нужно научить приложение **проверять данные,
пришедшие с сервера** (библиотека Zod).

> Если вы никогда не работали с TypeScript, ничего страшного: задание рассчитано именно на это.
> Начните с [пошаговой инструкции](docs/STEP_BY_STEP.md) и выполняйте её по порядку.

## Чему вы научитесь

| Тема | Где в проекте |
|---|---|
| Строгий режим TypeScript (`strict`), отказ от `any` | `tsconfig.json`, весь код |
| Размеченные объединения (discriminated unions) | статусы заказа, ошибки загрузки, состояние приложения |
| Обобщённые типы (generics) | `Result<T, E>`, `buildReport`, `getElement` |
| Утилитные типы (`Record`, `Pick`, `Readonly`…) | подсчёт по статусам, фильтр, ответ сервера |
| Брендированные типы | `Money`, `Percent`, `OrderId` |
| Типы DOM и защитники типа (type guards) | работа со страницей: элементы, события, `<select>` |
| Проверка данных на границе приложения | Zod-схемы для ответа сервера |

## Быстрый старт

Понадобятся [Node.js](https://nodejs.org/) версии **20.19 или новее** (лучше 22 LTS) и редактор
[VS Code](https://code.visualstudio.com/) (в нём TypeScript поддерживается сразу, без настройки).

```bash
npm install
```

```bash
npm run dev
```

Откроется браузер с приложением. Если не открылся, откройте адрес, который напечатан в терминале
(обычно <http://localhost:5173>). Остановить сервер — `Ctrl+C` в терминале.

Сейчас вместо сумм там `NaN`, а некоторые элементы интерфейса не работают. Так и задумано.
Запустите тесты:

```bash
npm test
```

Большинство тестов красные. В конце работы все тесты должны стать зелёными.

## Учебный сервер

Приложение получает заказы по адресу `/api/orders`. Отвечает на этот запрос маленький учебный
сервер из `server/mock-api.ts`, который запускается вместе с `npm run dev`. Режим сервера
переключается прямо в интерфейсе, в правом верхнем углу:

| Режим | Что присылает сервер |
|---|---|
| нормальный | правильный список заказов (`data/orders.json`) |
| присылает неправильные данные | заказы с ошибками: неизвестный статус, цена строкой (`data/orders-broken.json`) |
| отвечает ошибкой 500 | ошибку сервера вместо данных |

Сервер изображает «чужой» сервер, на который мы не можем повлиять, поэтому папку `server/`
менять не нужно.

## Правила

- **Тесты в папке `tests/` менять нельзя.** Ментор проверяет работу на исходных тестах.
- **Нельзя использовать `any`**, `// @ts-ignore`, `// @ts-nocheck` и `// @ts-expect-error` в `src/`.
  Это проверяют тесты.
- **Нельзя ослаблять `tsconfig.json`**: строгие проверки должны быть включены. Это тоже проверяют
  тесты.
- Не используйте оператор `!` (non-null assertion, например `order!.id`) и приведения `as`,
  чтобы «заглушить» компилятор. Тесты это не ловят, но ментор при проверке снизит оценку.

## Обязательные имена (контракт)

Тесты импортируют из ваших файлов определённые имена, поэтому называть их нужно ровно так:

| Файл | Типы | Функции и значения |
|---|---|---|
| `src/result.ts` | `Result<T, E>` | `ok`, `err` |
| `src/money.ts` | `Money`, `Percent` | `money`, `percent`, `sumMoney`, `multiplyMoney`, `applyDiscount`, `formatMoney` |
| `src/order.ts` | `Order`, `OrderStatus`, `OrderId` | `orderId`, `orderTotal`, `statusLabel`, `trackingNumber`, `customerContact`, `findOrder` |
| `src/schemas.ts` | — | `OrderSchema`, `OrdersSchema` |
| `src/api.ts` | `ApiError` | `fetchOrders` |
| `src/report.ts` | — | `buildReport`, `orderReceipt` |
| `src/ui/app.ts` | — | `startApp` |

Свои дополнительные типы и файлы добавлять можно.
