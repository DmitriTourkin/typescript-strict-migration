## Как устроена работа

### Что вы делаете

В проекте 10 файлов с кодом на JavaScript. Вы переводите их на TypeScript **по одному**, в
определённом порядке. С каждым файлом работаете по одному и тому же циклу:

```
переименовать .js → .ts
        ↓
добавить типы
        ↓
компилятор подчёркивает ошибки ──→ это настоящий баг? ──да──→ записать в отчёт → исправить
        ↓ нет, просто не хватает типа
дописать тип
        ↓
тесты этого файла зелёные → посмотреть в браузер → сохранить в Git (коммит)
```

Всего в коде **16 заложенных ошибок**, плюс проблемы в данных сервера, которые должен поймать Zod.

### Сколько времени займёт

Около 10–12 часов. Удобно разбить на 5 занятий:

| Занятие | Шаги | Время |
|---|---|---|
| 1 | Шаг 0 (подготовка) и шаг 1 (теория) | 2,5 ч |
| 2 | Шаги 2–6: строгий режим, `result`, `money`, `order` | 3 ч |
| 3 | Шаги 7–9: Zod, `api`, `report` | 2,5 ч |
| 4 | Шаги 10–13: интерфейс и финальная проверка | 2 ч |
| 5 | Шаги 14–15: отчёт, видео, сдача | 2 ч |

В конце каждого занятия делайте коммит и `git push` (см. [приёмы работы](#git-сохраняем-работу)):
так работа не потеряется, а ментор сможет посмотреть, как у вас дела.

### Как растут тесты

Всего тестов 58. После каждого шага их должно становиться больше. Если после шага зелёных
тестов меньше, чем в таблице, вернитесь и проверьте шаг.

| После шага | Зелёных тестов | Что должно стать зелёным |
|---|---|---|
| 0 (начало) | 14 из 58 | — |
| 5 `money` | 17 | весь блок «1. Деньги» |
| 6 `order` | 27 | весь блок «2. Заказы» |
| 7 `schemas` | 38 | весь блок «4. Zod-схемы» |
| 8 `api` | 44 | весь блок «3. Загрузка заказов» |
| 9 `report` | 48 | весь блок «5. Отчёты» |
| 10 `ui/dom` | 48 | — (готовим инструменты) |
| 11 `ui/render` | 51 | часть блока «7. Интерфейс» |
| 12 `ui/app` | 54 | весь блок «7. Интерфейс» |
| 13 `main` | 58 | весь блок «6. Проект переведён на строгий TypeScript» |

Блок «6. Проект переведён…» проверяет проект целиком, поэтому почти весь он зеленеет только в
самом конце. Это нормально.

## Шаг 0. Рабочее место и знакомство с приложением

После установки **перезапустите компьютер** (или хотя бы закройте и откройте VS Code заново):

### 0.2. Терминал: что это и как с ним работать

**Терминал** — окно, куда вводят команды текстом. В этом задании все команды запускаются из
терминала **внутри VS Code**: **Terminal → New Terminal** (или `` Ctrl+` ``). Терминал
откроется внизу окна.

Как вводить команду: напечатайте (или скопируйте) её и нажмите `Enter`. Команда выполняется,
пока не появится приглашение для новой команды. Некоторые команды (`npm run dev`,
`npm run test:watch`) работают постоянно, пока их не остановить: для этого нажмите `Ctrl+C`
в том же терминале.

> **Windows.** По умолчанию в VS Code открывается PowerShell, и в нём `npm` иногда выдаёт ошибку
> «выполнение сценариев отключено в этой системе». Чтобы этого избежать, переключите терминал на
> **Git Bash** или **Command Prompt**: в панели терминала нажмите стрелку `˅` рядом с `+` →
> **Select Default Profile** → **Git Bash**. Затем закройте старый терминал (значок корзины) и
> откройте новый.

Проверьте, что всё установилось. Каждая команда должна вывести номер версии:

```bash
node -v
```

```bash
npm -v
```

```bash
git --version
```

У `node` версия должна быть не ниже `v20.19`. Если команда пишет «не найдена» (`not found`,
`не является внутренней или внешней командой`), см. раздел
[«Если что-то пошло не так»](#если-что-то-пошло-не-так).

### 0.3. Представьтесь Git (один раз на компьютере)

Git подписывает каждое сохранение вашим именем и почтой. Подставьте свои данные (почту — ту же,
что на GitHub):

```bash
git config --global user.name "Иван Иванов"
```

```bash
git config --global user.email "ivan@example.com"
```

### 0.4. Получите свою копию проекта

Ментор пришлёт ссылку на репозиторий с заданием. Работать нужно в **своей копии**:

1. Откройте ссылку и войдите в GitHub.
2. Нажмите зелёную кнопку **Use this template → Create a new repository**. Если такой кнопки
   нет, нажмите **Fork**.
3. Название оставьте `typescript-strict-migration`. Выберите **Public** или **Private**; если
   Private, потом добавьте ментора: **Settings → Collaborators → Add people**.
4. Нажмите **Create repository**. Откроется страница вашей копии.
5. Нажмите зелёную кнопку **Code** и скопируйте ссылку из вкладки **HTTPS**.

Теперь скачайте копию на компьютер. В терминале перейдите в папку, где будете хранить проект
(например, `cd Documents`), и выполните, подставив скопированную ссылку:

```bash
git clone https://github.com/ваш-логин/typescript-strict-migration.git
```

Откройте папку в VS Code: **File → Open Folder…** → выберите папку `typescript-strict-migration`.
Если VS Code спросит «Do you trust the authors?», ответьте **Yes, I trust**.

Откройте терминал (**Terminal → New Terminal**): он сразу откроется в папке проекта. Установите
библиотеки проекта:

```bash
npm install
```

Это займёт минуту. Появится папка `node_modules`: в ней библиотеки, трогать её не нужно.
Предупреждения `npm warn` можно не читать; ошибкой считается только `npm error`.

### 0.5. Настройте VS Code

1. Включите автосохранение: **File → Auto Save**. Тогда тесты и браузер будут видеть изменения
   сразу.
2. Слева панель **Explorer** (`Ctrl+Shift+E`) — файлы проекта.
3. Откройте панель **Problems**: **View → Problems** (`Ctrl+Shift+M`). Здесь будет список всех
   ошибок TypeScript в открытых файлах. Это ваш главный инструмент.

> На macOS вместо `Ctrl` в сочетаниях клавиш используйте `Cmd`.

### 0.6. Запустите приложение

В терминале выполните:

```bash
npm run dev
```

Откроется браузер с приложением. Если не открылся, откройте адрес, который напечатан в
терминале после `Local:` (обычно <http://localhost:5173>).

Этот терминал теперь занят: в нём работает сервер. **Не закрывайте его**, пока работаете. Изменения
в коде браузер подхватывает сам, перезапускать ничего не нужно. Для остальных команд откройте
**второй терминал**: кнопка `+` в панели терминала.

### 0.7. Изучите приложение

Пройдите по всем элементам интерфейса и **запишите в черновик всё, что работает не так**:

- что написано в сводке над списком и в колонке сумм?
- у всех ли заказов виден статус?
- выберите в фильтре «Статус» вариант «Отменённые»;
- кликните по номеру заказа (`ord_…` слева), а потом по пустому месту в строке;
- переключите «Сервер» в режим «отвечает ошибкой 500», затем «присылает неправильные данные»,
  затем обратно в «нормальный».

Откройте **инструменты разработчика** в браузере: `F12` (на macOS `Cmd+Option+I`), вкладка
**Console**. Сюда браузер пишет ошибки JavaScript во время работы. Сейчас там может быть пусто,
но позже консоль не раз пригодится.

### 0.8. Запустите тесты

Во **втором** терминале:

### 0.9. Прочитайте код

Кода около 400 строк. Прочитайте файлы в `src/` в таком порядке: `result.js`, `money.js`,
`order.js`, `api.js`, `report.js`, затем `ui/dom.js`, `ui/render.js`, `ui/app.js`, `main.js`.
Посмотрите на данные в `data/orders.json`.

**Упражнение:** попробуйте найти ошибки «на глаз» и добавьте их в черновик. Позже вы сравните

### 0.10. Заведите отчёт и сделайте первый коммит

Отчёт заполняется **по ходу работы**, а не в конце: так ничего не забудется.

1. В VS Code в папке `docs` скопируйте файл `REPORT_TEMPLATE.md` (правый клик → Copy) и вставьте
   его в корень проекта (правый клик по пустому месту в Explorer → Paste). Переименуйте копию в
   `REPORT.md` (`F2`).
2. Заполните в нём раздел «1. Итог», колонку «До»: сколько тестов прошло и что вы увидели в
   браузере. Перенесите туда черновик с ошибками, найденными «на глаз».
3. Сохраните это в Git (что такое коммит, см. [приёмы работы](#git-сохраняем-работу)):

```bash
git add .
```

```bash
git commit -m "Шаг 0: заведён отчёт"
```

```bash
git push
```

При первом `git push` Git попросит войти в GitHub: откроется окно браузера, нажмите
**Authorize**. Если вместо окна Git спрашивает пароль, см.
[«Если что-то пошло не так»](#если-что-то-пошло-не-так).

**Совет для видео.** Чтобы в конце показать, как было «до», скачайте проект ещё раз в другую
папку: `git clone <ссылка> typescript-strict-migration-before`, затем в ней `npm install`.
Эту копию не меняйте.

## Приёмы работы: редактор, тесты, Git

Это справочник. Прочитайте его один раз сейчас и возвращайтесь, когда понадобится.

### VS Code

| Что сделать | Как |
|---|---|
| Переименовать файл | выделить в Explorer → `F2` |
| Увидеть текст ошибки | навести курсор на красное подчёркивание |
| Список всех ошибок | панель **Problems** (`Ctrl+Shift+M`); клик по строке открывает место ошибки |
| Узнать тип переменной | навести на неё курсор |
| Перейти к объявлению функции или типа | `F12` или `Ctrl`+клик |
| Найти по всему проекту | `Ctrl+Shift+F` |
| Перезапустить проверку TypeScript (если подчёркивания «застряли») | `Ctrl+Shift+P` → `TypeScript: Restart TS Server` |
| Предложения по исправлению | лампочка рядом со строкой или `Ctrl+.`. **Осторожно:** не соглашайтесь на варианты с `any`, `as` и `@ts-ignore` |

Если при переименовании файла VS Code спросит **«Update imports for …?»**, ответьте **No**:
импорты в проекте записаны без расширения и менять их не нужно.

Ошибки в файлах папки `tests/` (особенно `tests/types/contract.ts`) до конца работы — это
нормально: тесты ссылаются на типы, которых ещё нет. Исправлять папку `tests/` нельзя.

### Компилятор

```bash
npm run typecheck
```

Выводит все ошибки TypeScript в проекте. Если ошибок нет, ничего не печатает. Пример ошибки:

```
src/order.ts(51,86): error TS2339: Property 'qty' does not exist on type 'OrderItem'.
```

- `src/order.ts(51,86)` — файл, строка 51, символ 86;
- `TS2339` — код ошибки. По нему удобно искать объяснение в интернете, его же нужно указать
  в отчёте;
- остальное — текст: «Свойства `qty` нет у типа `OrderItem`».

Частые ошибки:

| Код | Текст (кратко) | Что значит |
|---|---|---|
| TS7006 | Parameter 'x' implicitly has an 'any' type | у параметра нет типа, добавьте его |
| TS7053 | Element implicitly has an 'any' type because expression … can't be used to index | обращение `obj[key]`, где компилятор не знает тип ключа или объекта |
| TS2339 | Property 'x' does not exist on type 'Y' | такого поля нет: опечатка или нужно сначала проверить `status` / `kind` |
| TS2322 | Type 'A' is not assignable to type 'B' | значение не того типа |
| TS2345 | Argument of type 'A' is not assignable to parameter of type 'B' | в функцию передали аргумент не того типа |
| TS2561 | Object literal may only specify known properties | в объекте лишний ключ (часто опечатка) |
| TS18047 / TS18048 | 'x' is possibly 'null' / 'undefined' | значение может отсутствовать, сначала проверьте |
| TS18046 | 'e' is of type 'unknown' | тип неизвестен, нужно проверить, например через `instanceof` |
| TS2366 | Function lacks ending return statement | не во всех ветках есть `return` |
| TS2307 | Cannot find module 'x' | пакет не установлен (`npm install x`) или неверный путь |

### Тесты

| Команда | Когда использовать |
|---|---|
| `npm test` | все тесты один раз |
| `npx vitest run tests/money.test.ts` | тесты одного файла (подставьте нужный) |
| `npm run test:watch` | тесты перезапускаются при каждом сохранении. Удобно держать открытыми во втором терминале. Выход — `q` или `Ctrl+C` |

Названия тестов говорят, что проверяется: `✓` — тест прошёл, `×` — не прошёл. Для каждого
упавшего теста ниже есть подробности:

```
 FAIL  tests/money.test.ts > 1. Деньги (src/money) > sumMoney() складывает суммы как числа
AssertionError: expected '100250' to be 350 // Object.is equality

- Expected:
350

+ Received:
"100250"

 ❯ tests/money.test.ts:23:48
```

- первая строка — какой тест упал;
- `Expected` — что тест ожидал, `Received` — что на самом деле вернул ваш код. Здесь ожидали
  число `350`, а получили строку `"100250"`;
- последняя строка — где в файле теста эта проверка. Откройте её, чтобы понять, что именно
  вызывается.

Если тест интерфейса падает с ошибкой вида `Timed out in waitFor`, значит, приложение не
отрисовало то, что ожидалось. Обычно выше в выводе есть настоящая причина (например, ошибка
в одной из функций).

### Git: сохраняем работу

**Коммит** — сохранённый снимок проекта с подписью. Делайте коммит **после каждого шага**.
Тогда, если что-то сломаете, всегда можно вернуться к последнему рабочему состоянию.

После каждого шага:

```bash
git add .
```

```bash
git commit -m "Шаг 5: money.ts"
```

`git add .` выбирает все изменения, `git commit` сохраняет их. Отправить коммиты на GitHub
(в конце занятия):

```bash
git push
```

Полезные команды:

| Задача | Команда |
|---|---|
| Что я изменил с последнего коммита | `git status` (список файлов), `git diff` (сами изменения, выход — `q`) |
| Отменить изменения в одном файле до последнего коммита | `git restore src/order.ts` |
| История коммитов | `git log --oneline` (выход — `q`) |

То же самое можно делать мышкой в VS Code: панель **Source Control** (`Ctrl+Shift+G`). Там видно
изменённые файлы, а клик по файлу показывает изменения «было/стало».

### Как просить помощь у ментора

Застряли больше чем на 30–40 минут — пишите ментору. Чтобы помочь можно было сразу, напишите:

# Часть 3. Миграция

## Шаг 2. Включаем строгий режим

### Эксперимент: отправная точка — `any`

Откройте `src/money.js` и наведите курсор на параметр `cents` в функции `money`. VS Code покажет
`(parameter) cents: any`. В JavaScript у всего тип `any`, «что угодно»: компилятор ничего не знает
о значениях и ничего не проверяет. Наведите курсор на `amounts` в `sumMoney`: тоже `any`. Именно
поэтому ошибки в коде никто не заметил.

Задача всей работы — пройти путь **от `any` до точных типов**: к концу ни одного `any` в коде не
останется. Первый шаг — включить строгий режим.

### Настраиваем компилятор

Откройте `tsconfig.json`. Это настройки компилятора TypeScript. Сейчас там:

```json
"allowJs": true,
"checkJs": false,
"strict": false,
```

- `allowJs: true` — в проекте могут быть `.js` файлы, и `.ts` файлы могут их импортировать.
  Благодаря этому файлы можно переводить **по одному**, а не все сразу.
- `checkJs: false` — компилятор не проверяет `.js` файлы.
- `strict: false` — строгий режим выключен.

Замените эти три строки на:

```json
"allowJs": true,
"checkJs": false,

"strict": true,
"noImplicitReturns": true,
"noFallthroughCasesInSwitch": true,
"noUncheckedIndexedAccess": true,
```

Следите за запятыми: в JSON после каждой строки, кроме последней в фигурных скобках, нужна
запятая. Если VS Code подчеркнул что-то красным в `tsconfig.json`, проверьте запятые.

Что включает каждая настройка:

| Настройка | Что делает |
|---|---|
| `strict` | включает группу проверок. Главные из них: **нельзя оставить параметр без типа** (`noImplicitAny`), **`null` и `undefined` нужно проверять явно** (`strictNullChecks`), **переменная в `catch` имеет тип `unknown`** (`useUnknownInCatchVariables`) |
| `noImplicitReturns` | функция должна возвращать значение во всех ветках |
| `noFallthroughCasesInSwitch` | нельзя случайно «провалиться» из одного `case` в следующий |
| `noUncheckedIndexedAccess` | `obj[key]` и `arr[i]` могут быть `undefined`, и это нужно проверить |

**Проверка.**

```bash
npm run typecheck
```

Ошибок быть не должно: файлов `.ts` в `src/` пока нет, а `.js` не проверяются. Начиная со
следующего шага каждый переименованный в `.ts` файл сразу проверяется по всем строгим правилам.

**Коммит:** `git add .` → `git commit -m "Шаг 2: строгий режим"`.

## Шаг 4. `result.ts` — обобщённый тип

**Что сделать.** Переименуйте `src/result.js` в `src/result.ts` и опишите тип:

- `Result<T, E>` — либо `{ ok: true; value: T }`, либо `{ ok: false; error: E }`;
- функция `ok(value)` возвращает успешный `Result`, `err(error)` — неуспешный.

Это **обобщённый тип** (generic): `T` и `E` — параметры, вместо которых потом подставляются
конкретные типы, например `Result<Order[], ApiError>`.

**Проверка.** `npm run typecheck` без ошибок. Настоящих багов в этом файле нет, число тестов
не меняется.

**Коммит:** `git commit -m "Шаг 4: result.ts"` (после `git add .`).

<details>
<summary>Подсказка</summary>

```ts
export type Result<T, E> = { ok: true; value: T } | { ok: false; error: E };
```

Тип `never` означает «такого значения не бывает». У `ok(42)` ошибки быть не может, поэтому удобно
возвращать `Result<T, never>`: такой результат подходит для любого типа ошибки.

```ts
export function ok<T>(value: T): Result<T, never> { ... }
```
</details>

## Шаг 5. `money.ts` — брендированные типы (разбираем вместе)

Этот шаг разобран подробно: на нём вы увидите весь цикл работы целиком, включая первую найденную
ошибку. Дальше будете действовать так же, но самостоятельно.

**1. Переименуйте** `src/money.js` в `src/money.ts`. В панели Problems появятся ошибки вида
`Parameter 'cents' implicitly has an 'any' type`. Это ошибки вида «не хватает информации»:
у параметров нет типов.

**2. Опишите брендированные типы.** В начале файла добавьте (как это работает, см.
[теорию](THEORY.md#5-брендированные-типы)):

```ts
declare const brand: unique symbol;
type Brand<T, B extends string> = T & { readonly [brand]: B };

export type Money = Brand<number, "Money">;
export type Percent = Brand<number, "Percent">;
```

**3. Напишите конструктор `money()`.** Это единственная функция, которая превращает число в
`Money`, поэтому здесь же проверяем, что число правильное:

```ts
export function money(cents: number): Money {
  if (!Number.isInteger(cents) || cents < 0) {
    throw new RangeError(`Сумма должна быть целым неотрицательным числом, получено: ${cents}`);
  }
  return cents as Money;
}
```

`as Money` здесь допустим: мы только что проверили число и сознательно ставим на него «метку».
Во всех остальных местах `as` не используем.

**4. Напишите `percent()` сами, по аналогии:** число от 0 до 100, иначе `RangeError`.

**5. Типизируйте `sumMoney`.** Она принимает список сумм и возвращает сумму:

```ts
export function sumMoney(amounts: readonly Money[]): Money {
  return amounts.reduce((total, amount) => total + amount, "");
}
```

`readonly` означает, что функция обещает не менять переданный массив. Сразу появляется ошибка:

```
TS2322: Type 'string' is not assignable to type 'Money'.
```

Функция должна вернуть `Money`, а возвращает строку. **Почему строку?** Посмотрите на последний
аргумент `reduce`: начальное значение `""`, пустая строка. А `"" + 100` в JavaScript — это
строка `"100"`, и дальше суммы не складываются, а склеиваются: `"" + 100 + 250 === "100250"`.
Можете проверить это в консоли браузера (`F12` → Console).

Спросим себя: «что увидел бы пользователь?» Вместо выручки 350 копеек — `"100250"`. Значит, это
**настоящий баг**.

**6. Запишите баг в отчёт.** Пример строки таблицы в `REPORT.md`:

| № | Файл, функция | Ошибка компилятора (код и текст) | Как проявлялась в приложении | Как исправил(а) | Что её поймало |
|---|---|---|---|---|---|
| 1 | `money.ts`, `sumMoney` | `TS2322: Type 'string' is not assignable to type 'Money'` | суммы склеивались как строки, в интерфейсе `NaN` | начальное значение `0`, результат через `money()` | возвращаемый тип функции |

**7. Исправьте.** Начальное значение `0`. Результат `reduce` — обычный `number` (сумма двух
`Money` — уже не `Money`), поэтому оберните его в `money(...)`.

**8. Типизируйте остальные функции** (`multiplyMoney`, `applyDiscount`, `formatMoney`).
`multiplyMoney` и `applyDiscount` возвращают `Money`, поэтому результат вычислений тоже
оборачивайте в `money(...)`. Это ошибки вида «не хватает информации», в отчёт они не идут.

**9. Проверьте тесты:**

```bash
npx vitest run tests/money.test.ts
```

Все 8 тестов зелёные.

**10. Посмотрите в браузер.** Сюрприз: приложение «зависло» на «Загружаем заказы…». Откройте
консоль (`F12` → Console): там `RangeError` из вашей функции `money()`, а в списке вызовов ниже
есть `orderTotal` из `order.js`.

Вы ничего не сломали. Раньше ошибка в `order.js` молча превращала суммы в `NaN`, а теперь
`money()` проверяет числа и сразу сообщает о проблеме. Это и есть смысл проверок: ошибка видна
сразу и там, где она возникла. Исправите её на следующем шаге.

## Шаг 7. `schemas.ts` — Zod-схемы

TypeScript проверяет только **ваш код**. Данные, пришедшие из сети, он проверить не может: они
появляются во время работы программы, когда типов уже нет. Если сервер пришлёт цену строкой
`"2490.00"`, программа ничего не заметит и посчитает ерунду. Поэтому данные проверяют на
**границе** приложения, в момент их получения. Для этого используем библиотеку **Zod**.

**Что сделать.**

1. Установите Zod (во втором терминале, `npm run dev` останавливать не нужно):
   ```bash
   npm install zod
   ```
2. Переименуйте `schemas.js` в `schemas.ts` и опишите схемы:
   - `OrderSchema` — один заказ. Используйте `z.discriminatedUnion("status", [...])`: это
     размеченное объединение в мире Zod;
   - `OrdersSchema` — массив заказов.
3. Схемы должны быть строже, чем «просто типы»:
   - `id` начинается с `"ord_"`;
   - цена — целое неотрицательное число;
   - количество — целое положительное число;
   - `email` — строка или `null` (поле обязательно, но значение может быть `null`);
   - `promoCode` необязателен.
4. Чтобы после проверки получались брендированные значения, используйте `.transform(money)` и
   `.transform(orderId)`.
5. Добавьте проверку, что схема и тип `Order` согласованы. Если они разойдутся, код перестанет
   компилироваться:
   ```ts
   type ParsedOrder = z.infer<typeof OrderSchema>;
   const _check = (parsed: ParsedOrder): Order => parsed;
   ```

**Проверка.**

```bash
npx vitest run tests/schemas.test.ts
```

Все 10 тестов зелёные. В браузере пока ничего не изменится: схемы ещё никто не использует.

**Коммит:** `git commit -m "Шаг 7: Zod-схемы"`.

Полезные части Zod: `z.object`, `z.string`, `z.number`, `.int()`, `.nonnegative()`,
`.positive()`, `.startsWith()`, `.nullable()`, `.optional()`, `z.literal`, `z.array`, `.extend()`.
Документация: <https://zod.dev>.

<summary>Подсказка: начало схемы</summary>

## Шаг 10. `ui/dom.ts` — типы DOM

Теперь интерфейс. Сначала прочитайте раздел [«Типы DOM»](THEORY.md#7-типы-dom-и-защитники-типа)
в теории.

**Что сделать.**

1. Переименуйте `src/ui/dom.js` в `dom.ts`.
2. Функция `getElement` сейчас возвращает просто `Element`. Но `Element` — это «какой-то элемент»:
   у него нет `value` (как у `<select>`) или `hidden` (как у `HTMLElement`). Сделайте функцию
   **обобщённой**: пусть она принимает третьим параметром «класс» элемента и проверяет, что
   найденный элемент действительно такого типа:
   ```ts
   getElement(root, '[data-role="mode"]', HTMLSelectElement) // → HTMLSelectElement
   ```
3. Типизируйте `span`.
4. **Сразу обновите вызовы** `getElement` в `src/ui/app.js` (он ещё на JavaScript): добавьте
   третий аргумент. Иначе приложение перестанет работать, ведь функция теперь ждёт три
   аргумента, а компилятор `.js` файлы не проверяет и об этом не предупредит:

   | Элемент | Третий аргумент |
   |---|---|
   | `mode`, `filter` | `HTMLSelectElement` |
   | `orders` | `HTMLUListElement` |
   | `summary`, `loading`, `error`, `details` | `HTMLElement` |

Настоящих багов здесь нет: этот шаг готовит инструменты для следующих.

**Проверка.** `npm run typecheck` без ошибок, в браузере приложение работает как после шага 9,
`npm test` показывает 48 зелёных тестов.

**Коммит:** `git commit -m "Шаг 10: dom.ts"`.

<details>
<summary>Подсказка: сигнатура getElement</summary>

```ts
export function getElement<T extends Element>(
  root: ParentNode,
  selector: string,
  type: { new (): T },
): T
```

`{ new (): T }` означает «что-то, что можно вызвать через `new` и получить `T`», то есть класс.
Внутри проверьте `element instanceof type`: после этой проверки компилятор знает, что `element`
имеет тип `T`.
</details>

### Если не проходит «типы соответствуют контракту»

Файл `tests/types/contract.ts` не запускается, а только компилируется. Он проверяет, что ваши
типы достаточно строгие. В нём есть строки вида:

```ts
// @ts-expect-error — обычное число нельзя выдать за Money
const rawNumber: Money = 1990;
```

`@ts-expect-error` означает: «на следующей строке **должна** быть ошибка». Если ваш `Money` — это
просто `number`, ошибки не будет, и компилятор сообщит `Unused '@ts-expect-error' directive`.
Посмотреть подробности:

```bash
npx tsc --noEmit -p tests/types/tsconfig.json
```

Найдите в `contract.ts` строку из сообщения и прочитайте комментарий над ней: там написано, что
именно проверяется.

## Если что-то пошло не так

**`node`, `npm` или `git` «не найдена» / «не является внутренней или внешней командой».**
Программа не установлена или терминал открыт до установки. Закройте VS Code полностью и откройте
снова. Не помогло — перезагрузите компьютер. Не помогло — переустановите программу.

**Windows: «выполнение сценариев отключено в этой системе» (`npm.ps1`).** Переключите терминал
на Git Bash или Command Prompt (см. [0.2](#02-терминал-что-это-и-как-с-ним-работать)).

**`npm install` завершился с `npm error`.** Проверьте версию Node (`node -v`, нужна 20.19+).
Удалите папку `node_modules` (в Explorer: правый клик → Delete) и выполните `npm install` снова.
Не помогло — пришлите ментору полный текст ошибки.

**`git push` спрашивает пароль, а обычный пароль не подходит.** GitHub не принимает пароль от
аккаунта. Самый простой путь — отправлять через VS Code: панель **Source Control** → кнопка
**Sync Changes** (или `…` → **Push**); VS Code предложит войти в GitHub через браузер.

**В браузере пустая страница или вечное «Загружаем заказы…».** Откройте консоль (`F12` →
Console) и прочитайте красную ошибку: в ней написано, в каком файле и функции проблема. Частые
причины: не обновили `index.html` после переименования `main.js` (шаг 13); забыли обновить вызовы
`getElement` в `app.js` (шаг 10); исправили `money.ts`, но ещё не `order.ts` (это ожидаемо, см.
шаг 5).

**Страница не открывается: «Не удаётся получить доступ к сайту».** Не запущен `npm run dev`, или
вы закрыли его терминал. Запустите снова и откройте адрес из терминала (номер порта может быть
другим, например `5174`, если `5173` занят).

**Подчёркивания в VS Code не совпадают с `npm run typecheck`.** Доверяйте `npm run typecheck`.
Чтобы обновить редактор: `Ctrl+Shift+P` → `TypeScript: Restart TS Server`.

**Ошибка `Cannot find module 'zod'`.** Не установлен Zod: `npm install zod`.

**Красные подчёркивания в `tests/`.** Это нормально до конца работы, папку `tests/` не меняйте.

**Случайно изменили файл в `tests/` или `server/`.** Верните его:

```bash
git restore tests server
```

**Запутались и хотите вернуть файл к последнему коммиту.**

```bash
git restore src/order.ts
```

Это отменит все изменения в файле после последнего коммита. Поэтому коммиты важно делать часто.

**Не понимаю ошибку компилятора.** Наведите курсор на подчёркивание и прочитайте текст целиком,
включая строки ниже первой: там часто объяснение. Поищите код ошибки (`TS2339` и т. п.) в
интернете. Посмотрите [таблицу частых ошибок](#компилятор). Не помогло — напишите ментору (см.
[как просить помощь](#как-просить-помощь-у-ментора)).

**Хочется написать `any` или `as`, «чтобы заработало».** Не надо: так ошибка не исправляется, а
прячется, и ментор снизит оценку. Это верный признак, что стоит перечитать нужный раздел теории
или спросить ментора.
