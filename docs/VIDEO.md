# План видеоотчёта (5–7 минут)

Записывайте экран с голосом. Подойдёт OBS Studio, встроенная запись экрана Windows (Win+G)
или macOS (Cmd+Shift+5). Выложите видео туда, откуда его можно посмотреть по ссылке
(YouTube с доступом по ссылке, Яндекс Диск, Google Drive).

| Время | Что показать |
|---|---|
| 0:00–0:30 | Кто вы и что за проект: веб-приложение магазина на JS, задача — строгий TypeScript |
| 0:30–1:30 | **Было:** приложение в браузере (`NaN` в суммах, не работают фильтр и клик) и `npm test` — сколько тестов красных. Покажите это на второй, нетронутой копии проекта (см. совет в шаге 0.10 инструкции): запустите в ней `npm run dev` |
| 1:30–3:30 | **2–3 самые интересные ошибки.** Для каждой: исходный JS-код → что сказал компилятор → исправление → как это выглядит в браузере. Хорошие кандидаты: перепутанные аргументы `applyDiscount` (поймал бренд), старые заказы после ошибки сервера (поймало размеченное объединение `AppState`), клик по номеру заказа (`event.target`) |
| 3:30–4:30 | **Граница приложения:** режим сервера «присылает неправильные данные» — что прислал «сервер» и как Zod это поймал |
| 4:30–5:30 | **Стало:** `npm run check` — всё зелёное; приложение в браузере во всех трёх режимах сервера |
| 5:30–6:30 | Выводы: что поняли про типы, что было сложным, какие ошибки TypeScript не ловит |

Советы:

- Перед записью увеличьте шрифт в VS Code (Ctrl/Cmd и `+`) и масштаб страницы в браузере,
  чтобы всё читалось на видео.
- Подготовьте ошибки заранее: например, временно верните баг в коде, чтобы показать, как
  компилятор подчёркивает строку, а потом исправьте.
- Не читайте отчёт вслух. Объясняйте своими словами, как коллеге.
